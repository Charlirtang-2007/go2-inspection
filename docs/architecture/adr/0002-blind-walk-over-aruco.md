# ADR-0002：放弃 ArUco 视觉定位，改为固定时长盲走

- 状态：accepted（演示阶段），可能回归
- 日期：2026-11-16
- 决策者：Charlirtang
- 相关：`architecture/overview.md`、`status/progress.md`

## 背景

早期方案用 ArUco 标记做点位定位：场地贴 A5 铭牌，机器狗识别后执行对应动作。MVP 版曾实现过 ArUco 识别，后来被删除。

演示前评估发现三个问题同时存在：

1. **识别不稳定**：光照、角度、距离都会影响识别成功率。
2. **部署麻烦**：要打印铭牌、贴场地、逐点调参，场地一变就要重来。
3. **资源不足**：没时间、没人、没精力在演示前把视觉方案调稳。

三条原因**同时成立，主次未做严格排序**。核心判断是：演示必须能跑，视觉方案的收益不足以覆盖它的不确定性。

## 决策

放弃 ArUco，改为**纯时间轴盲走**：

- 每个动作固定 `duration`（时长），靠时间而非视觉判断位置。
- **直行连发**防自停：持续发前进指令，避免狗中途停下。
- **转弯单发**防抽搐：转弯只发一次，避免高频循环导致抽搐。
- **起立加缓冲**：坐下后强制缓冲，解决起立瞬间重心突变导致的侧翻。

走位参数在 `run_inspection.py` 的 `do_action` 中维护。

## 被否方案

| 方案 | 结论 | 原因 |
| :--- | :--- | :--- |
| 纯 ArUco 视觉定位 | 否 | 识别不稳、部署麻烦、资源不足 |
| 视觉 + 盲走混合 | 否 | 混合方案调试成本更高，演示前无法收敛 |
| **纯固定时长盲走** | **采用** | 最简单、可控、演示能跑 |

“都试过，不好用，没时间，没人，没精力。”——这是当时的真实约束，不是技术优劣的严格结论。

## 后果

### 正面

- 演示能稳定跑通，不依赖光照和铭牌。
- 没有视觉依赖，场地布置成本大幅降低。
- 调试简单：偏航只改 `duration`。

### 负面

| 代价 | 表现 | 缓解 |
| :--- | :--- | :--- |
| **场地依赖强** | 地垫摩擦力变了，步长就要重调 | 现场 `duration` 微调；第一步 1.5s、后续 2.5s 为当前值 |
| **起始位置敏感** | 起始位偏一点，后面全偏 | 演示前校准起始位 |
| **不可复用** | 换场地要重新调参，不是“一次写好到处跑” | 接受，演示阶段只保一个场地 |
| **可能回归** | 以后条件允许可能重新引入 ArUco | 本 ADR 状态标为“可能回归”，不是永久否决 |

### 不做的事

- 不保留 ArUco 代码路径：已删除，避免维护两套走位逻辑。
- 不在演示前重启视觉方案：时间窗口不够。

## 后续

若未来回归 ArUco，应新开 ADR 记录回归理由，不直接改本 ADR。
