## 1. 这个项目现在是什么状态？

基于宇树 Go2 X 机器狗的 AI 巡检系统，**比赛演示已结束**。代码可跑，主要模块完成情况：

| 模块 | 状态 |
| :--- | :--- |
| K2B 边缘网关（跨网络控狗 + 视频流） | ✅ 完成 |
| 前后端通信（WebSocket） | ✅ 完成，死锁已修 |
| 三路检测器（preset / yolo / vlm） | ✅ 完成 |
| 告警 + 通知 + 录制 | ✅ 完成 |
| 物理走位（固定时长盲走，已放弃 ArUco） | ✅ 完成，现场需微调 `duration` |
| 姿态切换（坐立缓冲防侧翻） | ✅ 完成 |
| 滴漏识别 | ❌ 未训练，只有概念图 |
| 3D 模型流程 | ⬜ 计划中 |
| 复检转弯 | ⚠️ 部分完成，转弯角度待调 |

## 3. 哪些东西看起来能用但其实有坑？

| 坑 | 详见 |
| :--- | :--- |
| 盲走对场地地垫和起始位置敏感，换场地要重调 `duration` | ISSUE-0004 |
| 滴漏识别没有数据集，当前只覆盖烟雾 | ISSUE-0005 |
| K2B 长时间运行需注意散热 | ISSUE-0006 |
| 子线程里不能 `asyncio.run`，会跨事件循环死锁 | ISSUE-0001 |
| 坐下后不能直接发运动指令，必须加起立缓冲 | ISSUE-0002 |

## 4. 哪些决策看起来奇怪但有原因？

| 决策 | 为什么 | 详见 |
| :--- | :--- | :--- |
| 用 K2B 做网关，而不是前端直连 DDS | 前端无 DDS 绑定；WiFi 下组播不可靠 | `ADR-0001` |
| 放弃 ArUco，改固定时长盲走 | 识别不稳、部署麻烦、演示前资源不足 | `ADR-0002` |
| 端口固定 8000，`.env` 的 HOST/PORT 不生效 | 有意设计，不是 bug | `environment/ai-machine-setup.md` 步骤 5 |
